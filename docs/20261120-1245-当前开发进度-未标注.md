## 本轮完成（v0.0.2 → v0.0.3）

### 1. 修复二次部署必定失败（P0）

问题：`patch_picosnitch_ui` 要求 6 处目标字符串各命中恰好 1 次。首次部署已把它们替换掉，第二次部署时上游文件仍是已打补丁版本，`pip install --upgrade picosnitch==1.0.3` 发现版本已满足不会重装，于是补丁断言 `命中 1 次，实际 0 次` 直接失败，导致“push 即部署”只能成功一次。

修复（双重保险）：

- `install_picosnitch` 增加 `pip install --upgrade --force-reinstall --no-deps picosnitch==1.0.3`，每次部署先把上游文件还原成原始版本。
- `patch_picosnitch_ui` 改为幂等：目标字符串为 0 次、且替换后字符串已达到期望次数时视为已打过补丁并跳过；只有“既没命中旧串、也没命中新串”才报不兼容。

已验证：对同一假文件连续执行两次补丁脚本均成功，`interval=30000` 最终只出现 1 次。

### 2. 流量统计改为跨重启累计 + 自然月重置（P1）

问题：旧逻辑把 `tx_bytes` 与基线比较，而内核计数器重启归零。旧代码把归零当作“计数器回滚”并把基线重置为当前值，已用流量随之丢失，守卫实际只能统计“本次开机以来”的流量。

修复：状态文件从单行整数改为 `KEY=VALUE` 多行，记录 `PERIOD / TOTAL_BYTES / LAST_COUNTER / WARNED / ALERTED`：

- 每轮 `used = TOTAL_BYTES + max(current - LAST_COUNTER, 0)`，然后写回。
- 计数器回绕（`current < LAST_COUNTER`）时保留 `TOTAL_BYTES`，只对齐计数器。
- `PERIOD` 与当前 `date +%Y-%m` 不一致时清零累计并复位通知标记。
- 兼容旧格式：单行整数按“上次计数器、累计从 0 开始”读取，并视为当前周期，避免升级瞬间丢失已用量。
- 先落盘，再发预警/关机通知，避免关机过程中丢失最后一轮统计。

### 3. 新增 80% 预警与去重通知（P1 配套）

- 新增 `TRAFFIC_GUARD_WARN_PERCENT`（默认 80，0 表示关闭）。

- `TRAFFIC_GUARD_ACTION` 新增 `none`：只发通知不关机，便于先在真机观察一个周期。
