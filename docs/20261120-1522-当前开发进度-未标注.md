## 背景

用户告知 uw.sbbz.tech、ue.sbbz.tech 两台服务器的月流量配额都是 **50 GB**，而当时部署用的是默认 1024 MiB。ue 当时已用 501 MiB，按 1024 MiB 阈值继续会在当天触发关机。

## 本轮完成（v0.0.6 → v0.0.11）

### 1. 阈值调整为 50 GB（紧急）

两台服务器 `LIMIT_BYTES` 从 1073741824（1 GiB）改为 53687091200（50 GiB）。

- 80% 预警线 = 40960 MiB = 40 GiB
- Web 面板已确认显示 `50.00 GiB`

### 2. 修复 CI 重部署会覆盖现场配置（严重隐患）

**问题**：CI 部署（GitHub Actions）不带任何环境变量，安装脚本会用代码里的默认值重写配置文件：

| 配置 | 代码默认值 | 现场实际值 | 覆盖后果 |
|---|---|---|---|
| `LIMIT_BYTES` | 1024 MiB | 50 GB | **直接误关机** |
| `SMTP_HOST` | smtp.gmail.com | smtp.189.cn | 邮件发不出 |
| `ENABLE_MAIL_NOTIFY` | 0 | 1 | 静默失去通知 |

只要推送一次代码触发 CI 部署，这些现场调整就全被冲掉。这是比阈值本身更危险的问题。

**修复**：安装脚本启动时先读服务器上已有的 `/etc/default/traffic-guard` 和 `/etc/traffic-guard/gmail-notify.conf`，作为“环境变量未设置时”的默认值。显式传入的环境变量仍然最高优先级。

### 3. 修复过程中连带发现的两个自身 bug

**bug A：默认值遮蔽继承**

```bash
SMTP_HOST="${SMTP_HOST:-smtp.gmail.com}"   # 先赋了默认值
...
SMTP_HOST="${SMTP_HOST:-$(mail_existing SMTP_HOST)}"  # 永远拿不到空值
```

同理 `ENABLE_MAIL_NOTIFY` 先被赋 `0`，导致“已有配置时保持启用”的分支永不触发。

修复：所有可继承项先保持为空，继承完成后再补默认值。

**bug B：sed 中的 `$1` 被双层引号吞掉**

在 `ssh ... bash -c "..."` 内联脚本里测试时，`$1` 被外层 shell 展开成空串，导致读取出空值。这不是产品代码问题，但排查时容易误判，记录下来备查。

### 4. 邮件商限流保护

实测发现 189 邮箱**短时间连续发信会返回 `535 authentication failed: -200`**。间隔 20 秒后恢复正常。

原逻辑在单次检查同时越过预警线和阈值时会连发两封（预警 + 关机），第二封（真正重要的关机通知）可能被限流拒掉。

修复：越过阈值时直接置位 `WARNED`，不再补发预警，只发一封关机通知。
