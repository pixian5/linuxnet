## 优先级高

### 1. Bark 推送作为邮件兜底

服务器关机后，Gmail 邮件可能被忽略。用户已有 Bark：`https://api.day.app/<BARK_DEVICE_KEY>`。

建议：在 `send-shutdown-mail.sh` 增加可选 Bark 推送（`ENABLE_BARK=1` + `BARK_URL`），关机前同时发邮件和推送。推送内容无需附件，一行摘要即可。

### 2. 两台服务器尚未配置 Gmail 通知

当前 `ENABLE_GMAIL_NOTIFY=0`，也就是“关机前发信”实际未启用。需要用户提供 SMTP 授权码，或用 Bark 替代。

### 3. io_uring 零拷贝流量漏计

内核 7.0-azure 未暴露 `io_zcrx_recv_skb`，picosnitch 无法统计 io_uring 零拷贝接收的字节。如果 uw/ue 上跑的程序用到 io_uring（部分数据库、nginx 新版），出站/入站统计会有缺口。

建议：在文档中明确标注该限制；若确实有用例，考虑用 nftables 计数作为兜底校验。

## 优先级中

### 4. Web 端编辑预警线与动作

现在只能改阈值，`WARN_PERCENT` 和 `ACTION` 需手动改 `/etc/default/traffic-guard`。建议在表单中增加数字框与下拉框，复用现有 CSRF 校验。

### 5. 状态文件手动重置入口

误判或调整计费周期后只能登服务器删文件。建议 Web 端加"重置本周期统计"按钮。

### 6. 部署回滚

`git pull --ff-only` 后直接重装，新版本若失败会停在半新半旧状态。建议部署前记录 commit，失败时自动回退并重跑安装脚本。

### 7. 部署前记录服务器基线

本轮在 uw 上测试时，我自己的部署脚本里有 `rm -rf /var/lib/picosnitch`，导致已有的 114 条历史采集数据被清空。正式部署脚本没有这个行为，但应避免此类操作。建议在部署脚本中禁止删除数据目录。
