# v0.0.15 当前开发进度

本轮针对代码审查发现的四个问题做了修复，均为仓库侧修改，未在线部署。以下是新版本的行为，不是线上验收结果。

四项修复：

1. 部署工作流以部署用户身份调用安装脚本，云镜像禁用 root 直登时必然失败；改为先用 `sudo -n true` 校验免密 sudo，再用 `sudo -n bash scripts/install_linuxnet_stack.sh` 执行。
2. 凭据扫描把文档里的占位符（`your@189.cn`、`your_smtp_password` 等）当成真实凭据，按文档配置就会被本地钩子拦住；新增占位符豁免，真实样式的值仍拦截。
3. 启动标识文件不可读时，`$(cat ...)` 的失败让 `set -e` 直接终止脚本，日志一行都不留；改为显式判空并记录后退出。
4. 部署前的干净工作区检查带 `--ignored`，服务器上被忽略的 `__pycache__` 之类文件也会中止部署；改为只统计未跟踪的非忽略文件。

## v0.0.14 已完成（沿用）

| 环节 | v0.0.14 变更 |
|---|---|
| 凭据 | 现行文档中的已知泄露值已移除；本地提交钩子和持续集成检查新增内容及提交说明。规则命中只报类别，不回显原文。启用钩子及事故处置见[安全指南](security.md)。未轮换凭据，未清理提交历史。 |
| 网卡 | 安装前校验目标网卡的收发字节计数器；无法读取或不是非负整数即停止。运行中出站计数器缺失或非法时报错，不把未知流量当零，不更新该次基线。 |
| 同月重启 | 状态保存 `BOOT_ID`（内核启动标识）。同月发现启动标识改变时，把本次启动至首采的全部出站字节加入原累计，即使新计数器大于原读数也不漏计；跨月仍重置。旧状态无启动标识时不能追认重启。 |
| 邮件 | 120 秒期限覆盖一次通知的整个发送和重试过程，不是每次尝试各有 120 秒。超时发送终止信号，5 秒后仍未退出则强制终止；通知失败不阻断已配置的关机。 |
| 采集验收 | 记录连接表行号基线，再建立回环连接；须在数据库看到匹配本次探测的新连接行，历史数据或无关流量不算成功。 |
| 部署 | 只处理本仓库主分支推送成功的 CI（持续集成）提交；远端主分支、服务器最终版本均须等于本次提交标识。目录来源不符、工作区不干净或不能快进时停止，不覆盖现场。安装前校验免密 sudo，安装脚本以 sudo 执行（云镜像禁用 root 直登）。忽略文件不再阻断部署，仅未跟踪的非忽略文件会中止。 |
| 凭据检查误报 | 文档示例中的占位符（`your@`、`example.`、`<...>`、`${...}`、`xxxx`）放行；换成真实样式的值仍然拦截，真实泄露值的指纹比对不参与豁免。 |
