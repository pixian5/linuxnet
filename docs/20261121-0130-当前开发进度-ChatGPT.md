## 自动部署扩展为多机

原 workflow 只能部署一台，且仓库没有配置任何密钥，`ENABLE_DEPLOY` 也没设置。本轮补齐：

- `deploy.yml` 的服务器地址改为 `DEPLOY_SERVER_HOSTS`，支持逗号、空格、换行分隔；未设置时回退旧名 `DEPLOY_SERVER_HOST`。
- 逐台部署，任一失败即中止；已成功的机器保持新版本，不会回滚成半新半旧的不确定状态。
- 每台仍执行完整校验：符号链接、来源、分支、干净工作区、`FETCH_HEAD` 比对、快进、`HEAD` 复核、免密 sudo。

已配置（仓库 `pixian5/linuxnet`）：

| 名称 | 值 |
|---|---|
| `DEPLOY_SERVER_HOSTS` | `uw.sbbz.tech,ue.sbbz.tech` |
| `DEPLOY_SERVER_USER` | `x` |
| `DEPLOY_SSH_PRIVATE_KEY` | 本轮新生成的专用 ed25519 部署密钥 |
| `DEPLOY_KNOWN_HOSTS` | 两台服务器的 ed25519 host key |
| `ENABLE_DEPLOY`（变量） | `true` |

**部署密钥是新建的专用密钥**，不复用个人登录密钥，可随时从 `authorized_keys` 删除来吊销。公钥已写入两台服务器 `x` 用户的 `authorized_keys`，实测可登录且免密 sudo 可用。

## 排查记录

### 本机没有 uw/ue 的 SSH 配置

`~/.ssh/config` 只有 uk、or、oh、aws6 等条目，没有 uw/ue。逐一尝试密钥后确认可用的是 `x@<host>` + `/Users/x/ed25519`，两个用户名 `root`、`ubuntu` 均被拒（云镜像禁用 root 直登）。这一点与 v0.0.15 修复的“部署必须用 sudo 而非直接 root”一致。

### 主机密钥先核验再使用

`ssh-keyscan` 的结果与本机 `known_hosts` 中已有条目逐字节一致后才写入 `DEPLOY_KNOWN_HOSTS`，没有采用“运行时临时信任新密钥”的做法。

### ue 出现“检测到计数器回绕”日志

排查发现三条回绕日志时间戳为 `09:18`、`09:32`、`09:56 UTC`，正好跨在升级重启前后。原因是 v0.0.13 写的旧状态文件没有 `BOOT_ID`，按设计无法追认重启，只能按差值处理，而重启后计数器变小就落到了回绕分支。v0.0.16 已写入 `BOOT_ID`，此后重启会走“全部计入”分支。**这是旧版本的已知局限，不是新引入的问题。**

### 累计值有微小差异是正常的

验证过程中 `TOTAL_BYTES` 每次读取都比上一次略大（如 uw 从 `1915536083` 到 `1915676879`）。定时器每 10 秒跑一次，`LAST_COUNTER` 同步前进，属于正常增量。
