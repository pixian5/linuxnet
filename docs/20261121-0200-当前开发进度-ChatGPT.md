## 做了什么

1. **先备份**：`/Users/x/code/linuxnet-backup-20261121-0150.tar.gz`（含工作区）与 `/Users/x/code/linuxnet-git-backup-20261121-0150.git`（含完整 `.git`）。
2. **在副本上验证**：`git clone` 到 `/tmp/scrub-test`，跑 `git filter-repo` 重写并全量扫描，确认 0 残留、测试仍通过后，才对主仓库执行。
3. **同时清理文件内容和提交说明**：
   ```bash
   git filter-repo --replace-text /tmp/replacements_final.txt \
                   --replace-message /tmp/replacements_final.txt --force
   ```
   只加 `--replace-text` **不够**：它不处理提交说明，`54612d1` 里的口令仍会留着。
4. **替换为语义化占位符**，不是全抹成 `***`，这样文档仍可读：
   - Bark URL → `https://api.day.app/<BARK_DEVICE_KEY>`
   - 189 账号 → `<SMTP_ACCOUNT>`
   - SMTP 口令 → `<SMTP_PASSWORD>`
   - 测试样例 → `<TEST_MAILBOX>` / `<TEST_PASSWORD>`
5. **30 个提交全部重写**，`main` 强制推送。

## 修掉一个自己引入的漏洞

重写后测试挂了，暴露出 v0.0.15 “占位符豁免”写得太宽：

```python
# 修改前：任何尖括号内容都豁免
rb'|<\s*[A-Za-z_]+\s*>'
```

这意味着**只要把口令改成 `<随便什么词>` 就能绕过扫描**。改动：

```python
# 修改后：只认白名单里的占位符名
PLACEHOLDER_NAMES = (
    rb'SMTP_?PASS(?:WORD)?|SMTP_?USER|SMTP_?ACCOUNT|MAIL_?FROM|MAIL_?TO'
    rb'|BARK_?(?:DEVICE_)?KEY|WEB_?TOKEN|PASSWORD|TOKEN|SECRET'
)
```

测试样例也改为分段拼接（`'Zq9!' + 'realLooking' + 'Pass#1'`），避免测试文件本身在历史里留下完整口令串。

## v0.0.19：强制推送后 CI 不再报错

历史重写后的首次推送触发了 CI 失败：

```
无法读取待检查的本地提交或文件，检查未通过。
```

原因是 GitHub 事件里的 `BEFORE` 指向已被删除的旧提交，`git rev-parse` 解析失败。修正为：**基准提交不可达时退化为检查全部历史**，而不是跳过检查或直接失败。这样重写后的每个提交仍会逐条过规则与指纹。

验证：模拟 `--range 3cd91b7 b3f31a9` 输出“基准提交不可达（可能是强制推送），改为检查全部历史。”，退出码 0。修复后 CI 与 Deploy 均通过，两台服务器自动部署到 v0.0.19。
