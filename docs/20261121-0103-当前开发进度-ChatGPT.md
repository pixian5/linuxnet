# v0.0.16 当前开发进度

本轮实现“人工复位前不再关机 + 硬顶兜底”，属于仓库侧修改，未在线部署。以下是新版本的行为，不是线上验收结果。

## 背景：修复前的问题

旧实现里 `ALERTED` 只防重复发信，**不防重复关机**。超限后关机 → 人工开机 → 10 秒后定时器再次执行 → 再次关机。同月内基本无法再登录这台机器，除非从云控制台改配置或删状态文件。这个设计对“省配额”是对的，对“能上线处理问题”是错的。

## 新行为

状态文件新增 `SHUTDOWN_DONE`，记录本周期已执行自动关机的次数：

| 条件 | 行为 |
|---|---|
| 累计 < 阈值 | 正常计数，到预警线发一封预警信 |
| 累计 ≥ 阈值，`SHUTDOWN_DONE=0` | 发关机信 + 执行关机，`SHUTDOWN_DONE` 加 1 |
| 累计 ≥ 阈值，`SHUTDOWN_DONE≥1`，未到硬顶 | 只记日志，不关机、不重复发信 |
| 累计 ≥ 硬顶（阈值 × `HARD_LIMIT_PERCENT`，默认 150%）且 `SHUTDOWN_DONE=1` | 再强制关机一次，`SHUTDOWN_DONE` 变成 2 |
| `SHUTDOWN_DONE≥2` | 不再关机（硬顶只兜底一次，不做无限循环） |
| `ACTION=none` | 语义不变，本来就不关机，不做保护判断 |
| 跨月 / 首次运行 | `SHUTDOWN_DONE` 随其它标记一起归零 |

`HARD_LIMIT_PERCENT=0` 表示关闭硬顶，退化成“纯开关”：关机一次后直到人工复位都完全不再关机。

## 人工复位

Web 面板新增“超限关机保护”卡片，显示本周期已自动关机次数，并提供“人工复位（恢复自动关机）”按钮：

- 只清 `ALERTED` 和 `SHUTDOWN_DONE`，**不清空本月已用流量**，避免靠复位把账目抹掉。
- `WARNED` 保留，不会因为复位再收一封预警信。
- 复位使用独立 CSRF 令牌（`reset-shutdown`），拿改阈值的令牌提交会被拒。
- 状态文件不存在或无法解析时明确报错，不做任何修改。

## 关键实现细节

- **先写标记再关机**：`SHUTDOWN_DONE` 在 `write_state` 之前就递增并落盘。若放在关机之后写，`poweroff` 一旦生效就没有机会写文件，重启后仍会以为“没关过机”。
- **关机只认 `SHUTDOWN_DONE=1` 时的硬顶**：`SHUTDOWN_DONE≥2` 不再触发硬顶，否则每 10 秒又是一轮关机，等于回到旧问题。
- **`ACTION=none` 不累加次数**：否则切回 `poweroff` 时会误判“已经关过机”。
- **安装脚本继承 `HARD_LIMIT_PERCENT`**：与阈值、动作、预警线一样，CI 重部署不带变量时沿用服务器现场值。校验规则为“0 或大于 100”，避免填 50 导致每轮都关机。
