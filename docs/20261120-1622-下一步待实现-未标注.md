## 优先级高

### 1. Ubuntu 升级到 26.10（用户已确认要做）

用户要求把服务器升级到 Ubuntu 26.10。已确认的技术事实：

- 官方 meta-release：`stonking` = 26.10，`Supported: 1`；`resolute` = 26.04.1 LTS，`Supported: 1`
- **不支持从 24.04 跨版本直升 26.10**，必须先 24.04 → 26.04 LTS，再 26.04 → 26.10
- azure.archive.ubuntu.com 的 resolute 与 stonking 仓库都有 `linux-azure` 包
- 两台机器：Ubuntu 24.04.5 LTS，内核 7.0.0-1020-azure，磁盘 58 GB 可用，内存 887 MB
- 业务：`xbz.service`（80/443/2053/2083）、`bz.service`（8443）、linuxnet 四个单元

用户选择：先升 uw 一台观察，再升 ue。

备份方式：用户询问快照是否有免费额度（答：Azure 快照无免费额度，但 3.3 GB 用量约 $0.17/月，用完即删）。**待用户确认是否已在 Azure 做快照，或改为仅本地备份配置。**

升级步骤草案：

1. 本地备份 `/etc`、`/opt/linuxnet`、`/root/.acme.sh` 与 `dpkg -l` 包列表
2. uw 上 `do-release-upgrade` 到 26.04 LTS（`/etc/update-manager/release-upgrades` 当前 `Prompt=lts`，正好符合）
3. 改 `Prompt=normal` 再升 26.10
4. 每步验证：xbz/bz 端口监听、linuxnet 四单元 active、picosnitch 采集正常、邮件能发
5. 重点风险：picosnitch 2.2.1 的预编译 CO-RE 对象在新内核上是否仍可用；`/etc/xbz`、`/etc/bz` 配置是否被升级影响

## 优先级中

### 3. 50 GB 配额的计量口径可能不一致

云厂商的“50 GB/月”通常统计**出站公网流量**，而本项目的 `tx_bytes` 是**网卡全部出站字节**，包含内网通信、TCP 重传、协议开销、IPv6。

实测 ue 部署 1 小时产生约 600 MiB，按此推算月累计会远超 50 GB。**建议核对 Azure 控制台的实际计费数字与本地统计的比值**，必要时把阈值调低，留出计量差异缓冲。

### 4. Bark 推送作为邮件兜底

邮件可能进垃圾箱。用户已有 Bark：`https://api.day.app/<BARK_DEVICE_KEY>`。建议增加 `ENABLE_BARK=1`。

虽然现在有了 30 秒重试，但若 189 长期不可用（改密码、封禁），仍会彻底失去通知能力。

### 5. Web 端编辑预警线与动作

现在只能改阈值，`WARN_PERCENT`、`ACTION` 需手动改 `/etc/default/traffic-guard`。

### 6. 状态文件手动重置入口

误判或调整计费周期后只能登服务器删文件。

### 7. 部署回滚

`git pull --ff-only` 后直接重装，新版本失败会停在半新半旧状态。
