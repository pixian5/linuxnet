## P2

### 1. `pandas==2.0.3` 在 Ubuntu 24.04 上可能装不上

Ubuntu 24.04 默认 Python 3.12，而 `pandas==2.0.3` 没有 cp312 wheel，会退化为源码编译，大概率因缺少编译环境失败。

建议：改用 `pandas==2.2.3`（有 cp312 wheel），或在脚本开头检测发行版并给出明确报错，避免装到一半才失败。

### 2. 安装前缺少系统与版本前置检查

当前脚本直接 `apt-get update` 就开始装，没有检查是否 Ubuntu、架构是否 x86_64/aarch64、是否有 eBPF/BTF 支持。建议增加前置校验并在不满足时输出中文原因。

### 3. Traffic Guard Web 无法编辑预警线与动作

现在只能改阈值，`WARN_PERCENT` 和 `ACTION` 只能手动改 `/etc/default/traffic-guard`。建议在同一个表单里增加下拉框与数字框，并复用现有 CSRF 校验。

### 4. 状态文件缺少“手动清零”入口

误判或调整计费周期后，目前只能登录服务器删状态文件。建议在 Web 端加“重置本周期统计”按钮，点击后写入当前计数器并把累计清零。

## P3

### 5. 缺少真实服务器端集成测试

`tests/verify_traffic_guard.sh` 用假计数器覆盖了判定逻辑，但没有覆盖 systemd 单元、`systemctl` 调用与真实网卡读取。建议在一台测试 VPS 上跑一次全量部署并记录结果。

### 6. Deploy 工作流没有回滚

`git pull --ff-only` 后直接重装，若新版本安装失败，服务器会停在半新半旧状态。建议部署前记录当前 commit，失败时自动 `git checkout` 回上一个 commit 并重跑安装脚本。

### 7. README 与 VERSION 未联动

`VERSION` 文件没有被任何脚本或 CI 引用，容易与实际发布脱节。建议 CI 增加一步校验 commit 中是否同步更新了 `VERSION`，或在安装脚本里打印当前版本。

### 8. 邮件正文可读性

目前只列上传/下载前 5 程序，缺少时间范围和本周期起止说明。建议补充统计周期与生成时间。
