# 测试与验证经验

## 分层

| 层次 | 手段 | 覆盖 |
|---|---|---|
| Python Web 逻辑 | `unittest` + 真起 HTTP 服务 | 认证、CSRF、请求体限制、配置读写、状态解析 |
| Shell 判定逻辑 | 假计数器 + 假邮件脚本 | 累计、回绕、跨月、预警、阈值、去重 |
| 静态检查 | `shellcheck` | 引号、未定义变量、可移植性 |
| 真实部署 | 测试 VPS 跑一次全量安装 | systemd 单元、真实网卡、真实发信 |

## 关键手法

- **Shell 脚本要留可覆盖的路径变量**：`TX_FILE`、`STATE_FILE`、`MAIL_SCRIPT` 默认指向生产路径，但允许环境变量覆盖。这样测试可以完全在 `/tmp` 跑，不碰真实网卡也不关机。
- **用假的 `poweroff` 验证危险分支**：`ACTION=none` 分支必须有，否则“到底会不会关机”只能用真机验证。
- **断言计数而不是断言日志**：验证“只发一封”要看邮件计数，不是看日志里出现了关键字。
- **本地能跑 shellcheck**：`docker run --rm -v "$PWD":/mnt -w /mnt koalaman/shellcheck:stable <files>`。本机没装 shellcheck 时用它，比等 CI 报错快得多。

## v0.0.14 的验收判据

- 不用数据库非空证明探针可用：先记最大行号，再建回环连接，按本次端口和时间核对新增记录。旧库和繁忙主机都适用。
- 同月重启测试要覆盖新计数器**高于**旧计数器的情况，否则错误的差值算法也可能过关。网卡计数器缺失应返回失败，不能写零覆盖基线。
- 邮件超时测试看动作，而不只看日志：让发信替身挂起，确认 120 秒终止、再给 5 秒宽限，同时用关机替身确认后续动作未丢。
- 部署验收比对通过检查的提交标识与实际安装版本；检查通过后主分支已有新提交时，应停止旧任务而非部署最新代码。

## 坑

- 临时验证脚本本身也会写错（比如中文全角标点、`grep -c` 无匹配时退出码为 1）。验证脚本报 FAIL 时先确认是产品代码错还是脚本错。
- CI 里 `shellcheck tests/*.sh` 会把测试脚本也检查一遍，写测试时同样要过 shellcheck。
