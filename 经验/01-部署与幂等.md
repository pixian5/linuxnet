# 幂等部署经验

## 为什么“打补丁 + 版本固定”会互相打架

`pip install --upgrade 包==固定版本` 在版本已满足时**不会重装**，被改过的文件会一直留着。因此任何“安装后修改第三方源码”的脚本，第二次执行必然面对已打补丁的文件。

两种正确做法：

1. 强制还原：`pip install --upgrade --force-reinstall --no-deps 包==版本`，每次从零打补丁。
2. 幂等补丁：替换前同时统计“旧串”和“新串”出现次数。
   - 旧串命中期望次数 → 正常替换。
   - 旧串为 0 且新串已达期望次数 → 已打过补丁，跳过。
   - 其余 → 真正的不兼容，报错退出。

本项目两者都做了，因为“只做幂等”时若上游改了这段代码，新串也变成 0，会被误判为“已打补丁”，反而更难发现。加上强制还原后，上游变化一定会表现为“旧串 0、新串 0”，能被正确报错。

## 教训

- 安装脚本的“重复执行”必须显式测：对同一文件连续跑两次，而不是只跑一次看第一次通过。
- 任何 `raise SystemExit` 的断言式补丁，都要问一句“第二次部署时这行还成立吗”。
