# 流量统计经验（Linux 网卡计数器）

## 核心事实

`/sys/class/net/<iface>/statistics/tx_bytes` 是**内核 net_device 计数器**，从开机起累加，**重启后归零**。它和云厂商的月度流量配额没有关系。

因此直接用“当前值 − 基线”算已用流量，会在重启后把已用量算成 0（甚至因回绕得到负数）。旧实现把回绕当作异常并重置基线，等于每次重启都清空账目。

## 正确模型

状态文件要同时保存两个独立量：

```
PERIOD=2026-11          # 计费周期，用 date +%Y-%m
TOTAL_BYTES=10485760    # 本周期已累计出站
LAST_COUNTER=3000000    # 上次读到的内核计数器
WARNED=0                # 预警是否已发
ALERTED=0               # 超限是否已发
SHUTDOWN_DONE=0         # 本周期已自动关机次数（防开机即被再次关机）
```

每轮：

```
used = TOTAL_BYTES + (current - LAST_COUNTER)     # current < LAST_COUNTER 时增量为 0
```

- 计数器回绕：只把 `LAST_COUNTER` 对齐到 `current`，`TOTAL_BYTES` 不动。
- 跨月：`PERIOD` 变化时 `TOTAL_BYTES=0`、`LAST_COUNTER=current`、标记复位。
- 先落盘再关机，否则关机流程中最后一轮流量会丢。

## 坑

- **`set -u` 下解析状态要用 `|| [ -n "$line" ]`**：文件末尾没换行时 `read` 会返回非 0，循环体被跳过，最后一行读不到。
- **中文全角括号紧跟变量名会解析错**：`$desc（` 会被当成变量名的一部分。字符串里一律用 `${var}`。
- **升级时兼容旧格式**：旧状态文件是单行整数，没有周期字段。若不特殊处理，会被当成“新周期”直接清零。做法是“有旧计数器但无周期 → 视为当前周期，保留基线”。
- **通知要幂等**：`ACTION=none` 这类不关机的配置下，若不记录 `ALERTED`，会每 10 秒发一封信。
- **关机也要幂等**：只去重邮件不够。超限关机后人工开机，10 秒内会再次关机，人根本来不及处理。必须单独记“已关机次数”，并且 `SHUTDOWN_DONE` 要在 `poweroff` **之前**落盘——关机一旦生效，脚本没有机会再写文件。
- **“不再关机”要留硬顶**：纯开关（复位前永不关机）的风险是忘记复位就无限超量。默认 150% 再关一次，且只在 `SHUTDOWN_DONE=1` 时判定，否则到了硬顶又会每 10 秒关一次。
- **`ACTION=none` 不要累加关机次数**：否则之后切回 `poweroff` 会误判“已经关过机”，保护直接失效。
- **复位不要顺手清累计**：只清 `ALERTED` 和 `SHUTDOWN_DONE`。清 `TOTAL_BYTES` 等于给了个绕过配额的后门。
